# Content packs

A pack is everything a form needs, paste-ready. One pack = one site = one
client. A good pack means a listing takes 30–60 seconds.

## Grounding (read first)

- Fetch the client's own website **once per run**.
- Every factual claim — services, hours, phone, tagline, founding year — comes
  from the registry row or that live site.
- **Never invent** awards, reviews, credentials, team size or dates.
- Public business contact info (phone, the `hello@` address shown on the site)
  belongs in the pack. Account credentials never do.
- Registry row incomplete → stop for that client, name the missing field.

## Base pack (every category)

```
Business / product name :
Tagline (<= 60 chars)   :
Short description (<= 160 chars):
Long description (120-180 words):
Categories (2-4 suggestions):
Website URL             :
Anchor / keyword plan   :
NAP block               : name / address / phone
Public email            :
Image notes             : logo + cover, sizes the site wants
Site-specific notes     : submission URL, example listing pattern, quirks
```

## Uniqueness rule

**No two sites get the same description text.** Rotate the opening, the order of
services, the emphasis and the closing sentence. Same facts, different prose.
Duplicate paragraphs across 20 directories is the clearest spam footprint there
is — it is what gets listings deindexed.

The short and long descriptions are the ones that matter. Name, phone and
address should stay byte-identical everywhere (that consistency is the entire
point of citations).

## Anchor text

- Branded anchors by default (the business name, or the bare domain).
- Never a money keyword as the anchor on a directory listing.
- Exactly one in-body brand link on web 2.0 posts; a bio link is optional.

## Category-specific extras

| Category | Add |
|---|---|
| Business listing / citation | NAP block, business hours, service area, local keyword |
| SaaS / product directory | Tagline, feature list, pricing tiers, alternatives-to, maker info |
| Launch platform | Tagline, maker first-comment, gallery images, launch date |
| Review site | Feature list, pricing, category taxonomy — **profile only, never reviews** |
| Startup directory | Founding year, team size, funding stage, HQ |
| Web 2.0 post | 450–700 word article, 1 image, 1 in-body link, local detail |
| Doc / slide | Title <= 70 chars, description 100–200 words, tags, language, license |
| Infographic | Title <= 70 chars, description 150–300 words, tags, sources line, embed code |
| Community | A draft post only — the human posts it |

## Output

Show the queue as a table first:

`# · Site · DA/Spam · Rating · Submission URL · est. time`

then the pack blocks underneath. Sheet writes are opt-in per run — dry-run
(chat only) is the default, and a client's first run always shows packs for
review before anything is written.
